- 课表接口响应被 CDP **自动捕获**，捕获成功即**自动关闭登录窗口**——用户可能还在课表页，窗口突然关闭；

# 追加：三个问题修复（导入报错 / 学期名称无法输入 / 卡顿优化）

## 问题 1：导入预览确认报错 `Wrong API use: tried to bind a value of an unknown type (undefined)`

**根因（两层叠加）**：
1. **Electron 层**：`preload.confirmImport(result)` 在合并导入（不传 options）时执行 `invoke('import:confirm', result, undefined)`——顶层 undefined 参数触发 Electron 序列化报错；`backup.importJson()` 无参调用同款隐患
2. **sql.js 层（真正的元凶）**：`buildUpdateClause` 只过滤"整个元组为 undefined"，未过滤"字段值为 undefined"——单字段更新（如 `update(id, { color })`）时其余字段以 undefined 传入 SQL 参数，sql.js 绑定 undefined 抛完全相同消息的错误。该路径由"导入时同名课程颜色统一"与"课表配色自动修复"触发（`repo.update(id, { color })`），也潜伏在课程编辑保存（单字段更新）中

**修复**：
- `preload.ts`：`confirmImport` / `backup.importJson` 有值才传参（避免顶层 undefined）
- `updateHelper.ts`：`buildUpdateClause` 过滤条件补 `field[1] === undefined`（核心修复）
- 回归测试：新增 `tests/updateHelper.test.ts`（4 用例：单字段更新/跳过空元组/全空返回 null/表达式保留）

## 问题 2：新建学期时无法输入学期名称

**根因**：`.semester-form`（含输入框的容器）带 `backdrop-filter: blur(20px)`——软件渲染（当时禁用了硬件加速）下大半径 backdrop-filter 干扰内部控件交互，且 Chromium 的 backdrop-filter 容器对子控件事件存在已知问题。

# 追加：抓取失败排查（代码审查 + 健壮性修复）

## 用户报告

"抓取失败，报错了"（官网抓取课表失败），要求代码审查排错。

## 审查结论

对抓取全链路（schoolIpc → schoolSessionService.collectScheduleData → schoolIndexImporter → checkDuplicatesAndConflicts → import:confirm）逐段审查：

**未发现本次改动引入的确定性 bug**（解析器 15 个测试覆盖、类型检查通过、用户 DB 中已有新学期与 31 门课程说明链路部分成功过）。最可能的失败原因是**运行时环境问题**（学校会话过期 / 未进入课表页就点就绪 / WebVPN 网关），但存在 3 个**健壮性缺口**会让排障困难：

1. `school:user-ready` 的 async 流程无 try/catch —— 任何异常会让登录窗口工具条**卡死在"抓取中"**，且错误无记录
2. 抓取失败信息不落盘 —— 用户报错时无法离线定位
3. `collectScheduleData` 中单域 Cookie 读取异常会中断整轮候选域尝试

## 修复

1. `schoolIpc.ts`：`school:user-ready` 包 try/catch（异常 → 工具条 error + 诊断记录）；新增 `recordFetchError()` 把最近一次失败写入 `{userData}/data/school-fetch-error.log`（含 attempts 逐域诊断）
2. `schoolSessionService.ts`：`collectScheduleData` 候选域循环包域级 try/catch（单域失败计入 attempts，不中断整轮）

- `npm run typecheck`：✅ 0 错误
- `npm run test`：✅ 81/81 通过
