# Part B：Day 4 正式任务：HTML / 剪贴板导入 + 去重 + 冲突处理

Day 4 目标：

1. 实现 htmlImporter.ts 基础版本。

3. 完善 normalizer.ts。
4. 完善 source_hash 去重逻辑。

# 任务 1：实现 htmlImporter.ts 基础版本

路径：

src/importers/htmlImporter.ts

要求：

1. 支持读取保存下来的课表 HTML。
2. 如果没有真实东北农业大学课表 HTML，则创建 mock fixture：

tests/fixtures/sample-timetable.html

3. htmlImporter 输出必须经过 normalizer，转换成和 JSON importer 一致的 normalized course event 结构。
4. 解析失败时返回清晰错误，不要崩溃。
5. HTML 解析可以先支持简单 table 结构。
6. 如果无法可靠解析真实学校 HTML，不要硬编假逻辑骗过测试。先完成 mock HTML parser 框架，并在文档中说明真实 HTML 需要后续提供样本。

# 任务 2：实现 clipboardImporter.ts 基础版本

路径：

src/importers/clipboardImporter.ts

要求：

1. 支持从剪贴板文本导入。
2. 支持简单文本格式，例如：

数据库原理与应用 张老师 成栋楼A101 周一 1-2节 1-16周
大学英语 李老师 成栋楼B202 周三 3-4节 1-16周 双周

3. 需要识别：

   * 课程名
   * 教师
   * 地点
   * 星期
   * 节次
   * 周次
   * 单双周

4. 识别失败时显示错误项和原始文本。

5. 输出必须经过 normalizer。

# 任务 3：完善 normalizer.ts

要求：

1. JSON、HTML、Clipboard 最终都输出统一结构。

2. 统一校验：

   * courseName 必须存在
   * weekday 必须是 1-7
   * startSection <= endSection
   * startWeek <= endWeek
   * weekPattern 只能是 all / odd / even

3. 统一生成 source_hash。

source_hash 应该基于：

* semester name
* courseName
* teacher
* location
* weekday
* startSection
* endSection
* startWeek
* endWeek
* weekPattern

注意：

note 不参与 source_hash，因为备注是用户手动编辑字段。

# 任务 4：重复导入去重

要求：

1. 导入确认前，先检查数据库中是否已有相同 source_hash。

2. 如果已有相同 source_hash：

   * 标记为 duplicate
   * 默认不重复导入
   * 在 ImportPreview 中显示重复项

3. 同一个 JSON / HTML / 剪贴板重复导入，不应该重复创建课程和 course_event。

# 任务 5：手动修改保护

要求：

1. 如果数据库中已有相同或疑似相同课程事件，并且 updated_manually = true：

   * 不允许静默覆盖
   * 在 ImportPreview 中标记为 conflict

2. 冲突项至少显示：

   * 数据库中的旧值
   * 新导入的值
   * 哪些字段不同
   * updated_manually 状态

3. 默认策略：

   * 保留用户手动修改
   * 不覆盖 note
   * 不覆盖 location
   * 不覆盖 weekday
   * 不覆盖 section
   * 除非用户明确选择覆盖
